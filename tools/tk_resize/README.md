# Production Tk resize comparison

## Manual test harness

Run `python -m tools.tk_resize.manual_launcher` from the repository root. It opens this checkout's
production Tk Main/Quick UI with fake content and an isolated profile. Both test
windows stay visible until the main test window closes; there is no ten-minute
deadline. Launching again raises the existing session. The launcher uses
the established local runtime, keeps external-effect guards, and writes local
reports under `logs/tk_resize/manual-launches/`. Topmost behavior is fixture-only.
Pass `--check` to verify paths/runtime without opening windows, or `--private-check`
to verify preparation on a private desktop.

This harness compares two source versions of the actual Tk UI. The offline
configuration, transport fixtures and process sampler live in `tools/tk_resize/`;
the UI is `TranslatorApp` and `QuickTranslateManager` from the selected source checkout.

Finish implementation and its requirement audit before starting the consolidated
validation. Do not run these workers after each edit or edit shared source while
a worker is alive. Keep original reports when repairing a failed scope.

```powershell
python -m tools.tk_resize.final_validation --label <run-id> --final-validation
python -m tools.tk_resize.comparison --baseline logs/tk_resize/baseline-20261029 --output logs/tk_resize/<run-id>/pairs --final-validation
```

Use the first command for the final batch. The second is its pair step, shown for
an explicitly scoped recheck; do not run both to duplicate a successful comparison.
The batch requires a current, complete implementation audit and otherwise refuses
to start.

The CLI requires a new output directory. Each pair uses the same Python executable,
private desktop, fake services, input and production grip methods. It retains
source archives/digests, owner/child PIDs, raw logs, `manifest.json`, `events.jsonl`,
`metrics.json`, `summary.json`, `scenario.json`, `resize.json` and native PNGs.
No paid API, live credentials, clipboard, global hotkeys, registry or input injection
is used. The unchanged full-suite/count-floor commands and Tk gallery matrix also
belong to the consolidated batch, not to each individual worker.

The quick workload drives the same grip path that handles a non-native gesture;
it does not merely call `geometry()` on a fixed body. Full-document measurement
and release costs are recorded separately. Real system sizing, Escape, no-activate
focus behavior during native capture and compositor response still need a controlled
physical gesture. Callback duration, event-loop cadence and geometry notifications
are not frame presentation or pointer-to-photon measurements. No automatic FPS
claim or whole-TODO completion is generated by this harness.

Memory is reported in bytes with an explicit before/after delta. Idle CPU needs at
least 30 seconds; lifecycle covers 50 open/resize/theme/close cycles. The retained
growth heuristic is a review aid, not a proof that no leak exists. Fresh-process
startup does not imply a cold operating-system cache. The final decision needs the
resource/visual/physical evidence as well as passing automated regressions.

All 18 workloads have a standard profile. Six demanding surfaces also have a matched
Japanese profile with 150% text and a 1.5 Tk DPI multiplier. The multiplier is a
simulation; it does not establish physical mixed-monitor DPI transitions. Pairing
checks include actual final outer sizes, content hashes, annotation/link counts
and runtime/scaling identity. A mismatch is reported, rather than silently comparing
different windows or workloads.

Both application versions run from checked source extractions with bytecode writing
disabled, so the current worktree's bytecode cache is not a special advantage for
the candidate. Actual source origins are verified. This still does not clear OS
file/model caches or control unrelated background load.

CPU samples distinguish steady, resize, settle and capture phases. Kernel lifetime
working-set/commit peaks cover earlier startup allocations even though regular
private-byte sampling begins after UI construction. The values are different
views of memory and must not be added together. Startup records process creation
to main-show return, separately from popup reopen/Expose notifications; neither
claims a cold OS cache or the first visible compositor frame.

After the last motion the driver stops its recurring 16 ms tick. Bounded idle
observations require mapped descendants, Text metrics and ScrollArea geometry to
settle for at least 120 ms, with a 10-second failure deadline. The original
500 ms `resized` capture is retained alongside a distinct `settled` capture.
`settlement.json` records every observation and release-to-observed-stability
latency; it does not measure paint/presentation. Missing/failed settlement fails
the pair gate. A later correct layout never erases an earlier clipped image or
proves smoothness. Hidden/lifecycle cases report settlement as not exercised.

For a separately arranged visible session, the same worker accepts an explicit
manual mode. It opens the production Tk UI with fake data for a bounded interval;
the human or the authorized desktop tool performs the gesture. It does not script
dragging, capture the public desktop, read a live profile or unblock clipboard/input
effects. Do not use the old Qt/Notepad time slot as current desktop availability.

```powershell
python tools/tk_resize/worker.py --source . --output logs/tk_resize/<manual-run-id> --scenario two-windows --manual-visible-desktop --manual-seconds 120
```

The session ends when the main fixture closes or its deadline expires. Geometry
and resource logs are retained for review; opening the fixture alone does not pass
the physical-drag gate. Automated batches never supply this manual flag.

After a completed original full run reports failures, preserve it and recheck the
affected modules together. A resumed batch accepts `--resume-batch <batch.json>` and
`--recheck <run.json>` only when the retained full JUnit meets the original floor,
all failed cases actually pass in the current recheck, and changed source/test/asset
scope has executed coverage. It does not label that chain a fresh full-suite pass.
Repeat `--recheck` in chronological order when a later repair only changes tooling.
The count checker remains unchanged: it reads a derived reconciled JUnit containing
copied actual results, clearly labeled as mixed-run evidence with per-case provenance.
Original failed reports are retained verbatim.

Unchanged original build/clipboard skips may also appear in a broad affected scope.
They remain explicit skips, with the same identity/reason and test-file hash, and
never count as executed repair coverage. New/changed skips and a regression from
passing to skipped are rejected. The real clipboard guard is not disabled to
make a validation aggregate green.

A recheck that declares complete module execution replaces that module's older
case identities. Renamed or reparameterized passing tests are retired with explicit
provenance, rather than counted alongside their replacements. Original failed or
guarded cases cannot disappear this way, nor can cases from an unchanged test file.
Older partial-case rechecks keep their original merge behavior. Originals stay intact.

Markdown-only follow-up notes may differ from the latest tested source. The resumed
record lists those files and both source digests; testcase provenance retains the
actual tested digest. Any code, test, asset or unexplained manifest change still
fails. The implementation audit must independently cover the current TODO/source.

Before each measured Quick trajectory, the fixture prepares one bounded rectangle
through production grip press/release and observes convergence without an event pump.
Preparation has its own phase/report/capture; canonical content, measured motion
sequence, runtime and DPI are retained. Both workers must record the same start
rectangle; missing/different starts fail. Natural initial captures remain available.
The separate `--natural-gesture-start` path retains an untouched first gesture for
regression testing; it does not replace prepared comparative measurements. Both
paths are exercised with the two-window workload at standard/large presentation.
